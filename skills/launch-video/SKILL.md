# /launch-video

Understand this software product and turn its **actual interface and workflows** into a launch film.

Not "AI, make a cool startup video." Every frame comes from the repository: real screens
captured from the running app, real feature names backed by source files, the product's own
colors and type, and copy that passed claim verification.

## Invocation

```
/launch-video https://github.com/user/project
/launch-video https://github.com/user/project --tone cinematic
/launch-video . --duration 20 --format vertical
/launch-video https://github.com/user/project --tone "minimal Apple-style" --platform linkedin
/launch-video https://github.com/user/project --no-music --no-sfx
```

| Option | Values | Default |
|---|---|---|
| `--duration` | 15–30 seconds | 24 (platform presets adjust) |
| `--format` | `landscape` (16:9), `vertical` (9:16), `square` (1:1) | `landscape` |
| `--tone` | `polished` `cinematic` `minimal` `playful` `technical` `app-store` `bold`, or freeform | inferred from the product's design language |
| `--platform` | `linkedin` `x` `instagram-reel` `youtube-short` `product-hunt` | generic |
| `--voice` | flag | off (recorded; narration is not generated by this build) |
| `--no-music` / `--no-sfx` | flags | music + sfx on |
| `--no-run` | skip running the app (static + source-derived visuals) | run |
| `--no-render` | build everything but do not render | render |
| `--quality` | `draft` `looks` `delivery` | `looks` |

Parse the invocation first. A pasted URL with no flags means defaults. Freeform tone text is
preserved as creative direction and mapped to the nearest preset by the connector.

## Step 1 — Run the connector

Prefer the MCP tool when the `hyperframe-launch` server is available:

```
create_launch_video({ repository_url, duration, format, tone, platform, music, sfx, quality })
```

Otherwise run the CLI from this plugin's root (`<plugin-root>` is the directory containing this
skill's parent `skills/` folder; run `npm install && npm run build` there once):

```bash
node <plugin-root>/bin/hyperframe-launch.js <repo> [flags] --out launch-output
```

The connector does the whole pipeline automatically:

```
Repository → Deep codebase analysis → Detect frontend → Run app → Browser exploration
→ Screenshots → UI/UX analysis → Product DNA → Story plan → Storyboard → Claim verification
→ Hyperframes composition → Music/SFX/beat alignment → hyperframes check → render → share copy
```

Report its progress lines to the user as they arrive (✓ Repository analyzed, ✓ Application
launched, ✓ 8 screens discovered, …). Do not paraphrase them into marketing language.

**Gate:** `launch-output/launch-result.json` exists and `quality-gate.json` has no failed
`error`-severity checks. If the app could not run, the result says `runtime_unavailable` with the
reason — that is not a failure of the run; the film is then built from source-derived visuals
(real code cards + README words). Tell the user which path was taken.

## Step 2 — Review the creative artifacts (read, don't rewrite)

Read, in this order:

1. `launch-output/product-dna.json` — the source of truth. Verified features with evidence,
   captured screens with scores, user flows, visual identity, verified vs unsupported claims.
2. `launch-output/launch-plan.md` — what the product is, the strongest verified angle, hook, UI
   moments, CTA, tone, visual identity, and the claims deliberately kept out.
3. `launch-output/storyboard.md` — the scene-by-scene contract (source screen, text, motion,
   transition, audio).

Judge it with the rubric in [references/review-rubric.md](references/review-rubric.md). The
usual weak spots are: the hook is the product name because nothing else verified; a workflow
scene uses a low-value page (about/settings) because the crawl found little; the tone preset does
not match what the user asked for.

## Step 3 — Refine (only when it earns its place)

You may change copy, scene order, timing, and motion — but every on-screen line must remain
traceable to `product-dna.json` (`verified_claims`, `verified_features`, screen headlines) and
must not contain numbers about users, revenue, accuracy, speed, customers, funding or downloads.
Never invent a screen. Never restyle the product's colors.

To refine:

1. Edit `launch-output/composition/index.html` directly (it is a standalone Hyperframes
   composition: one paused GSAP timeline, one `<section class="clip">` per scene, real
   screenshots under `assets/screens/`). Load `hyperframes-core`, `hyperframes-animation`,
   `hyperframes-keyframes` for the contract if you change motion. Keep the reading floor: short
   label ≈ 0.8 s settled, sentence ≈ 0.3 s/word, never fast-in-then-gone.
2. Re-run the gate and render:
   ```
   render_launch_video({ output_dir: "launch-output", quality: "looks" })
   ```
   or `node <plugin-root>/bin/hyperframe-launch.js render launch-output --quality looks`.

If `hyperframes check` fails, fix the reported finding in `index.html` (contrast findings come
with a suggested color; layout findings name the selector) and re-run. Do not bypass with
`--no-contrast` unless the only failures are contrast findings on decorative elements.

## Step 4 — Deliver

Tell the user:

- Where the video is (`launch-output/launch.mp4`) and the poster (`launch-output/poster.png`,
  already baked as frame 0 so every platform's idle thumbnail is the hero frame).
- One sentence on what the film does creatively, naming the real screens it uses.
- Where the share copy is: `launch-output/share-copy/{linkedin,x,product-hunt,short-caption}.md`.
- Which claims were kept out and why (from `claim-verification.json`) — this is a feature.
- Offer: re-roll a scene, change tone, change format, or try a different hero screen.

## Creative laws (apply to every launch video)

- **Real UI or nothing.** At least one major portion of the film is the actual product UI. The
  better the UI, the more of it we show. Generic graphics never replace the product.
- **Specific.** The angle names a real screen and a real feature. "A calm, keyboard-first notes
  app" beats "Revolutionizing productivity."
- **Verified.** No metric that source code cannot prove. No fabricated users, revenue, accuracy,
  performance, customers, funding or downloads.
- **Preserve the product's design.** Its background, accent, radius, type. Hyperframes' default
  look is never imposed.
- **Readable.** UI stays legible (no scale beyond ~1.14, no spins); text is fast-in, then holds.
- **Restrained audio.** One music bed, at most five SFX, one impact at the hero reveal, an
  audio-reactive glow that breathes — never an equalizer.
- **15–30 seconds.** Hook (0–3s) → reveal → core workflow → key features → hero UI → CTA.

## Security posture (do not weaken)

Repositories are untrusted. The connector installs dependencies with lifecycle scripts disabled,
runs the app with a scrubbed environment on a private port, blocks external network from the
browser, never reads `.env`-style files, redacts secret-looking values before analysis, and never
sends `.env` contents anywhere. If a repository's dev script shells out to docker/ssh/curl-pipe-sh
it is not run. Do not add `--dangerously` style overrides on the user's behalf.
