# /frameo

One command. Give it a repository, get a 30-second launch film made from the product's **actual
interface and workflows** — real screens captured from the running app, real feature names backed
by source files, the product's own colors and type, and copy that passed claim verification.

```
/frameo https://github.com/user/project
```

That is the whole interaction. Options exist but are never required:

```
/frameo https://github.com/user/project --tone cinematic
/frameo . --format vertical
/frameo https://github.com/user/project --platform linkedin --no-sfx
```

| Option | Values | Default |
|---|---|---|
| `--duration` | 15–30 s | **30** |
| `--format` | `landscape` (16:9), `vertical` (9:16), `square` (1:1) | `landscape` |
| `--tone` | `polished` `cinematic` `minimal` `playful` `technical` `app-store` `bold`, or freeform | inferred from the product's design language |
| `--platform` | `linkedin` `x` `instagram-reel` `youtube-short` `product-hunt` | generic |
| `--no-music` / `--no-sfx` | flags | music + sfx on |
| `--voice` | flag | off (recorded; narration is not generated by this build) |

## What to do when `/frameo <repo>` is invoked

1. **Run Frameo.** Use the MCP tool `frameo` when the `frameo` server is available:
   ```
   frameo({ repository_url: "<repo>", ...any flags the user gave })
   ```
   Otherwise run the CLI from this plugin's root (run `npm install && npm run build` there once):
   ```bash
   node <plugin-root>/bin/frameo.js <repo> [flags]
   ```
   Relay its progress lines verbatim (✓ Repository analyzed, ✓ Application launched,
   ✓ 8 screens discovered, …). Frameo does the whole pipeline itself:

   ```
   Repository → Deep codebase analysis → Detect frontend → Run app → Browser exploration
   → Screenshots → UI/UX analysis → Product DNA → Storyboard → Claim verification
   → Hyperframes composition → Music/SFX/beat alignment → hyperframes check → render → share copy
   ```

2. **Deliver.** Tell the user:
   - the video: `frameo-output/frameo.mp4` (30 s) and the poster `frameo-output/poster.png`
     (baked as frame 0, so every platform's idle thumbnail is the hero frame);
   - one sentence on what the film shows, naming the real screens it uses
     (`frameo-output/storyboard.md`);
   - the share copy: `frameo-output/share-copy/{linkedin,x,product-hunt,short-caption}.md`;
   - which claims were deliberately kept out (`frameo-output/claim-verification.json`) — this is
     a feature, say so.

   If the app could not run, the summary says `runtime_unavailable` with the reason and the film
   is built from source-derived visuals (real code cards + README words). Say which path was
   taken. If Hyperframes is unavailable or `check` failed, `render-status.json` has the reason;
   never claim a video exists when it does not.

3. **Only if the user asks for a change** (different tone, format, hero screen, copy): re-run
   `/frameo <repo>` with the corresponding flag. Every on-screen line must stay traceable to
   `product-dna.json`; never invent a screen, never add numbers about users, revenue, accuracy,
   speed or funding, never restyle the product's colors.

## Creative laws Frameo enforces

- **Real UI or nothing.** The product's captured interface carries the film; generic graphics
  never replace it.
- **Specific.** The hook is the product's own tagline or a verified feature, ≤ 8 words.
- **Verified.** No metric source code cannot prove; generic SaaS phrases are banned.
- **Preserve the product's design.** Its background, accent, radius, typography.
- **Readable.** UI never scales past ~1.14; text is fast-in, then holds.
- **Restrained audio.** One music bed, ≤ 5 SFX, one impact at the hero reveal, a subtle
  audio-reactive glow — never an equalizer.
- **30 seconds.** Hook → reveal → core workflow → key features → hero UI → CTA.

## Security posture (do not weaken)

Repositories are untrusted. Frameo installs dependencies with lifecycle scripts disabled, runs the
app with a scrubbed environment on a private port, blocks external network from the browser, never
reads `.env`-style files, redacts secret-looking values before analysis, and never sends `.env`
contents anywhere. Dev scripts that shell out to docker/ssh/curl-pipe-sh are not run.
